# 《勇者小队全灭了。》杯赛 Mod

杯赛 Mod v0.5.5 适用于 Windows x64 Steam Build 26845264。使用 MelonLoader 0.7.3 和当前游戏生成的 IL2CPP 互操作程序集。

## 开赛

杯赛沿用正常游戏保存的启动语言。中文启动时杯赛显示中文，其他语言启动时杯赛显示英文。

1. 退出已打开的游戏，在游戏目录双击 `Launch-Cup.cmd`。也可以给 Annihilated.exe 加参数 `--annihilated-cup`。
2. 在标题界面的「杯赛配置」选择比赛模式、目标和战斗方式，输入杯赛编号、地图种子、限时和起始楼层，然后点「开始杯赛」。指定 Boss 时，在选定 Boss 后从可达的剧情分支中选一条。两种模式都从起始楼层首区开始计时。「献祭仪式」直接进入献祭场景，开局属性分配按其原有计时规则处理。
3. 地图岔路由选手自行决定。达成指定目标、正式战败或限时用尽时停表。
4. 日常游戏从 Steam 正常启动。比赛模式单独使用 NaninovelData/CupSaves 下的新档目录。普通读档、快速读档和回滚在杯赛中禁用。一局结束后退出游戏，再用启动脚本开下一局。

原版存档页和文字输入框打开时停表。固定演出和原版快进正在推进的对白也会停表。地图选格、整备和战斗判定按比赛时间计入，包括按住 Ctrl 时。限时使用同一个计时器。

## 比赛模式

- **指定结局**可按同伴选择本地攻略列出的 23 个可达目标，包括坏结局、剧情回退和提前收束。「序章」下可选择「献祭仪式」。原版的剧情条件仍然生效。战士的「接受战士 · 故障」在首次到达故障结局时停表。若选「故障后的偶像尾声」，故障段之后继续计时，直到尾声。
- **指定 Boss**使用选手选定的可达剧情分支。击败选中的 Boss 时停表。目标包含 11 场主线或固定精英战。同名重战独立识别。尚未击败目标时，进度按到达的楼层和区域、是否进入目标战，以及可识别的目标战阶段排列。

「杯赛配置」中的「快速过剧情」默认开启。开启后，两种模式均按所选细分分支自动推进对白、演出和剧情选项。关闭后，对白和演出正常播放，剧情选项由选手点击。两种情况下，目标分支限制和原版剧情条件均生效，战斗、地图选格和整备均由选手操作。

## 多届配置

- **起始楼层**。默认第 1 层。跳层仍会执行原版的开局初始化，然后直接进入指定层的第 1 区。从第 2 层起，每跳过一层，主角和选定同伴的起始等级增加 10 级，以 1 级为基准。第 2 层是 11 级，第 3 层是 21 级。经验和属性按原版规则初始化，携带开局技能和装备。可选楼层取决于目标和剧情分支。魔王和僧侣低循环结局可填 6 进入额外区域。

- **F9 重打上限 / 每次 SL 罚秒**。配合「重打当前房间」v1.0.1 使用。次数填 0 禁用 F9，罚秒填 0 则无需加时。读档期间显示「SL 读档暂停」。成功读回战斗开场时消耗一次并立即加上罚秒，之后按游戏状态恢复计时。失败或被拒绝的 F9 不扣次数和罚秒。SL 罚秒计入比赛限时，和死亡罚秒分别写入成绩。
- **允许死亡 / 每次死亡罚秒**。正式死亡以原版进入战败流程为准。剧情要求的特殊回退、同伴倒地和原版在同一场战斗内救回主角不扣。每次正式死亡立即把设定的秒数加到计时，额度内可走原版复活；超额按战败结束。允许死亡填 0 时首次正式死亡即结束杯赛。罚秒计入比赛限时。

- **开局诅咒 / 开局属性点**。在进迷宫前发放。属性点大于 0 时，主角会在首次进迷宫前死亡一次，进入原版属性分配菜单。也可以在属性点为 0 时手动开启这次死亡。强制死亡和演出免罚，死亡额度为 0 也可以使用。分点、兑换及其他可操作步骤照常计时。复活后保留开局装备和未花掉的诅咒。目标为「献祭仪式」时，比赛在下迷宫前结束，因此该目标不提供这组开局选项。

- **死亡菜单的诅咒兑换**。可兑换池从第 1 层累计到当前层。例如从第 3 层开局也可以兑换第 1、2、3 层的装备。候选来自宝箱、普通敌人、精英、首领抢夺和已映射的事件奖励，以有原版兑换价格的道具为限。同伴分支按地图层数计算，兑换价格和槽位限制按原版结算。

从杯赛配置底部进入「娱乐规则」，首页为武器规则。

- **跑刀**。成功夺取能攻击的武器并入包后，自动打开这把武器的殉刃攻击条。选手亲自完成一次攻击判定，命中或打空都会损坏武器。原目标已经死亡时直接损坏武器。
- **背包武器上限**。留空不限，填 0 则不保留武器。超过上限时，新武器自动碎成诅咒。若同一次殉刃夺取行动确实损坏了一把旧武器，新武器可以占用腾出的名额。药水等无攻击能力的道具不计入上限。
- **仅主角命毁夺取武器**。只保留主角用「命毁」实际从敌人手中抢到的武器。开局、宝箱、事件、兑换、同伴夺取等来源的武器自动碎成诅咒。与上限同时开启时，主角用命毁夺来的武器也占一个名额。
- **严苛的训练几乎要了我的命**。敌人从开战起，无需破防即可被夺取身上尚未夺取的武器。选用能夺取的招式时，夺取区域由原版生成，玩家按原版战斗方式判定。主角及原生没有夺取手段的同伴，在前后排都可额外选择「命毁」，普通攻击照常可用。与「仅主角命毁夺取武器」同时开启时，同伴夺来的武器会转成诅咒。

自动碎掉的武器按原版破坏收益给诅咒。原版收益为 0 时按原版兑换价折算，最低 1 点。开局碎武器所得的诅咒加到设定的开局诅咒上。

在「战斗与火堆规则」页可追加一项原版火堆合成，设置怪物血量和攻击倍率，并禁用一名战斗角色。「夺取武器后多一个回合行动」默认关闭。开启后，夺取者在成功夺取的当轮多进行一次行动。「怪物被夺取武器后下一回合受伤倍率」独立生效，默认 ×2，填 ×1 即为原伤害。倍率只作用于被夺取的怪物，从下一轮我方行动开始到本轮我方行动结束。再次夺取会刷新时效，倍率保持为所填数值。

怪物攻击倍率同时作用于招式预告和我方血条预测。招式预告显示格挡前的伤害，血条预测继续按游戏规则结算格挡等防御效果。

禁用角色原本属于当前队伍时，剩下的一名单独上场。「接替被禁用角色的行动」开启后，该角色也执行空出的那次行动。士兵缺席时，同伴可按原版条件使用「命陨」。

每位选手在游戏内填写当届设置。主办方公布模式、目标、战斗方式、编号、种子和限时。开跑后配置锁定，成绩按当届规则分组。指定 Boss 时，成绩记录选手的细分路线，同一目标下选用不同路线的选手可同场排名。点「随机」可生成练习种子。限时填 0 表示不限时。

Mod 将上次开跑的配置保存在 UserData/AnnihilatedCup/cup.json，下次打开界面时自动带出。

默认配置为 Cup-001、勇者「并肩走出迷宫」、概率模式、种子 20261113。当前版本的固定种子覆盖已接入的地图生成、格子随机流与道具抽取入口。生成地图时，以固定的 50 理智选择地图事件池，避免前一区选路改变新区的基础格子。进入格子后的实际理智和剧情条件仍按原版结算。事件转盘、尚未跑过的分区、不同路线汇合和跨机器复现仍需要实测。

## 成绩

停表后点屏幕左侧杯赛 HUD 下方的「导出比赛成绩」。提交 `UserData/AnnihilatedCup/exports` 下的 JSON 和从配置页开始录制的完整录像。文件名、JSON 的 `RunCode` 和 HUD 显示同一个八位本局编号。重复点导出会更新同名文件。

成绩记录配置、用时、已完成的检查点、终止原因、地图指纹和按顺序排列的关键事件。SL 会记开始恢复、成功或失败，正式死亡会记是否超限，开局免罚死亡单独记录。每条事件带本次罚时、累计罚时、比赛用时和从本局启动起算的实际时间。达成目标时记录目标 ID。进度和赛果仍自动写入 `UserData/AnnihilatedCup/results`，崩溃时残留的 `running` 记录需要裁判处理。

裁判解压一键安装包后，可打开 `Cup-Referee.html`。先用「读取规则 JSON」载入主办方的 `cup.json` 或已确认的参考成绩，再点「应用当届规则」。批量导入选手提交的 JSON 后，点本局编号查看疑点与时间轴，按编号核对录像。最后在「暂定排名」点「导出 CSV」。具体步骤见同目录的 [REFEREE.md](REFEREE.md)。

在 [源码仓库](https://github.com/BrickAZ/Annihilated-Mods/tree/main/CupMod) 中，也可以将选手提交的 JSON 放在同一目录，再运行 `pwsh -File CupMod/RankResults.ps1 -EventId Cup-001 -Results "成绩目录"`。脚本按比赛配置指纹分组。完成目标的选手按用时排名，其余选手按最远检查点排名，同点并列。

## 源码和验证

在源码仓库目录执行 `dotnet build CupMod/AnnihilatedCup.csproj -c Release "-p:GameRoot=游戏目录"`。构建依赖已由 MelonLoader 生成的互操作程序集。给 `--annihilated-cup` 追加 `--annihilated-cup-smoke` 或 `--annihilated-cup-boss-smoke`，可在游戏中验证开局、地图及模拟终点事件。追加 `--annihilated-cup-mage-smoke` 可使用种子 20261113 验证原版技能、铁剑和药水的初始化，再通过原版地图按钮进入哥布林战并读取初始战斗模式。自检成绩写入 verification 目录。各目标从序章到终点的完整实跑仍待验证。
